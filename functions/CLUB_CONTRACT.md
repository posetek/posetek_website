# Club callable contract (2026-09-07)

`issueClubPlayerInvitation({organizationId,playerId})` returns `{playerId,code}` for an existing
unclaimed club player. A manager/admin or the assigned team coach can issue a fresh 128-bit
version-2 signup code. Issuing again invalidates the previous code. Claiming binds the same
player document; claimed or ambiguous Auth bindings cannot be reset through this endpoint.
Existing club endpoints use Firebase Auth callers and reject anonymous access.
Legacy `CLUB-` redemption requires verified email matching the invite. New managed
activation uses a private UID-bound link; preflight and new-account password setup
are callable without a signed-in user. All authorization remains server-owned.
See [managed account access](../docs/EMAIL_FREE_ACCOUNT_ACCESS.md) for the current
email-free setup, recovery and failure contract. Errors are Firebase HttpsError.

- `getClubContext({organizationId?: string})` -> `{role:'admin'|'manager'|'coach'|'player'|'none', organizations:[{id,name,schemaVersion:2}], organization: {id,name,schemaVersion:2}|null, teams:[{id,organizationId,name,coachUIDs:[uid],playerIds:[playerDocId]}], staff:[{userUID,email,firstName,lastName,role,teamIds,status}], invitations:[{id,email,firstName,lastName,role,teamIds,status:'pending'|'claimed'|'revoked'|'expired',expiresAtMillis}], players:[{id,firstName,lastName,organizationId,teamId,canIssueSignupCode:boolean}]} `. Admin gets org directory; with no organization selected returns directory, empty detail arrays. Manager gets all club teams/staff/invitations/players. Coach gets assigned teams and roster only; staff/invitations empty. Player returns their own club/team only; players own profile only. Non-club legacy caller returns role none and empty arrays. Membership is canonical; organization directory memberUIDs is derived. Club users currently belong to one club.
- `createClubOrganization({name})` -> `{organizationId}`. Verified @posetek.net admin only. Creates schemaVersion2 club; no automatic admin membership required.
- `saveClubTeam({organizationId,teamId?:string,name})` -> `{teamId}`. Admin or own-club manager; creates or renames team. Team IDs immutable.
- `createClubStaffInvitation({organizationId,email,firstName,lastName,role:'manager'|'coach',teamIds:string[]})` -> `{invitationId,code,expiresAtMillis}`. Admin/manager. 7-day expiry, email-bound, >=128-bit random code (prefix CLUB-), hash only stored server-side. Code returned once; user copies/shares manually. TeamIds must belong to club; managers use []. Pending staff placeholder created in org staffProfiles. Never email automatically.
- `redeemClubStaffInvitation({code})` -> `{organizationId,role:'manager'|'coach',teamIds}`. Signed-in verified invited email. Single-use atomic binding creates canonical membership + coaches/{authUid} mirror, binds pending staff profile. Existing unrelated coach/athlete/org identity rejected without overwrite. Existing same-club membership rejected (use management endpoint).
- `createClubStaffInvitation` additionally accepts `activationMode:'manual'` and returns `{invitationId,grantId,code,activationUrl,expiresAtMillis,email,accountMode,purpose}`. Its `ACCESS-` link binds a fixed Auth UID; existing accounts sign in and new accounts choose their own password. Staff verification flags are unchanged. Only the trusted account-access service can redeem this mode.
- `replaceClubStaffInvitation({organizationId,invitationId})` replaces a pending/expired invitation with a new manual activation link and invalidates its predecessor atomically. Started activations require review rather than replacement. Invitation projections expose `activationMode` and `activationStatus` for truthful UI states.
- `setClubStaffTeams({organizationId,userUID,teamIds:string[],status?:'active'|'inactive'})` -> `{ok:true}`. Admin/manager. Changes coach assignments or revokes/reactivates staff membership. Managers require empty teamIds. Cannot disable yourself or last active manager. Authoritative membership checked on every request. Derived coach roster/team lists refreshed atomically.
- `revokeClubStaffInvitation({organizationId,invitationId})` -> `{ok:true}`. Admin/manager. Revokes pending invite.
- `setClubPlayerTeam({organizationId,playerId,teamId})` -> `{ok:true}`. Admin/manager. Moves a player ALREADY belonging to the club to a team in same club; preserves ID, auth binding, Storage paths. Roster mirrors updated. Import of legacy players is separate reviewed migration.

Stored authority: organizations/{orgId}/members/{authUid} `{userUID,email,firstName,lastName,role,teamIds,status:'active'|'inactive'}`. players `organizationId`, `teamId`. Legacy coach aliases never authorize migrated player. Top-level teams derived roster; coaches canonical `{userUID,organizationId,organizationRole,teamIds,members,...}`. No client writes to memberships/teams/club authority. Legacy organization codes cannot join schemaVersion2 clubs or reassign a club coach/player into legacy orgs.

- `createClubPlayer({organizationId,teamId,firstName,lastName,height?,weight?,phone_number?,preferredFoot?,signupEmail?})` -> `{playerId,code}`. Admin/manager or coach assigned to selected team. Creates immutable player document ID with club/team fields, unclaimed player signup code version2; returns code compatible with existing `redeemPlayerSignupCode`. Club clients must use this endpoint, never legacy direct coach/player roster writes.

- `getTeamLeaderboard({teamId?:string})` retains its existing projected metrics response and returns `{playerId,coachId,teamId?,organizationId?,athletes}`. Club athletes default to their canonical team. Staff/admin may specify an authorized team. Stale legacy rosters cannot include migrated players.
- `importClubLogo({organizationId,websiteUrl})` -> `{logoStoragePath,logoUrl,logoSourceUrl,websiteUrl}`. Admin/own-club manager only. The trusted importer fetches a public HTTPS website, selects and validates a bounded public PNG logo, and stores it in the club branding namespace. `organization` and `organizations` descriptors include these four fields when present.

Validation: `node --test functions/*.test.js` covers handler authority, replay and competing claims, identity preservation, malformed migrated identities, assignment revocation, legacy admission, projections, and branding. The separate mobile repository's `firebase/tests/clubs.test.mjs` exercises real Firestore/Storage SDK requests against both the canonical sources and the scoped production candidate using the existing Firebase emulators. A passing handler test does not substitute for that emulator receipt.
